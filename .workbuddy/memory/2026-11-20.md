## sync.py：切换到 registry 代理 + 过滤彻底前置（重写）

- 网络结论：本机 `hub.docker.com` 直连超时、代理 502；`gh-proxy.org`/`gh-proxy.com` 是 GitHub 加速代理且本机连不上（代理 SSL 失败 / 直连被重置），不能代理 Docker Hub。`hub.coding-space.cn` 是可用的 **Docker Registry v2 代理**（`/v2/`、`/_catalog` 分页、`/tags/list`、`/manifests/<tag>` 的 docker-content-digest 均正常）。
- 改动：把 Docker Hub REST API（`/v2/repositories/...`）整体换成 registry 代理接口。
  - 常量 `REGISTRY_API=https://hub.coding-space.cn/v2`，新增参数 `--registry-api`；`registry_host()` 从它提取 host。
  - `list_repositories` 用 `_catalog` 分页 + 命名空间前缀过滤；`list_tags` 用 `tags/list`；新增 `parse_next_link` 解析 Link 头分页。
  - 新增 `get_source_digest`：GET manifest（带多架构 Accept），多架构取当前平台子 manifest digest，单架构用响应头 docker-content-digest。
  - `collect_images` 只收集 `(repo,tag)`，digest 延后到过滤后按需取（全部已同步时零 manifest 请求）。
  - `source_image()` 让 `docker pull` 也走代理 host；`source_key()` 专用于匹配接口已同步列表（不带 host）。
  - `main` 过滤前置：`pending` 为空直接 return（不登录、不逐条日志、不跑 docker）。
- 实跑 `python3 sync.py --list`：扫 17 仓库 230 镜像，接口 230 全命中 → 「全部已同步，无需操作」直接结束。mock 验证 4 分支（全跳过 / 部分待同步 pull 走代理 / --force / --no-skip-synced）全通过。
